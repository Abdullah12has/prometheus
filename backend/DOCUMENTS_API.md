# Financial documents API

All endpoints require the operator session and CSRF header for writes. Uploads are stored under the private local data directory; no remote URL fetching occurs.

`POST /api/companies/{company_id}/documents` accepts multipart field `document` containing one PDF (`application/pdf`) or XHTML/iXBRL (`application/xhtml+xml`, `application/ixbrl+xml`) up to 25 MiB. The response is `202` with an id, SHA-256, size, and `queued` status. A durable `document.extract` job is inserted. `GET /api/companies/{company_id}/documents` lists uploads; `GET /api/documents/{id}` returns processing status and proposed financials; `GET /api/documents/{id}/source` returns the original authorized document.

The parent job runner calls `await process_document(document_id, sessionmaker, llm, settings.data_dir, job_guard=None)`. `job_guard`, when supplied, is a synchronous lease-validity callback. PDF parsing runs off the event loop, has a 200-page and 4 MiB extracted-text limit, and sends bounded text batches to `llm.extract`. Every PDF result must include an exact quote from its declared page, a supported metric, decimal amount, currency, period, and scope. Unsupported or uncited claims are discarded. If only some LLM batches succeed, the document status is completed with an explicit partial-extraction warning in `warning`.

iXBRL facts are read locally with DTD/entity declarations rejected across UTF-8, UTF-16, and UTF-32. Numeric conversion supports the XBRL International `num-dot-decimal` and `num-comma-decimal` transforms, their apostrophe variants, and older `numdotdecimal`, `numcommadecimal`, and `numdotdecimalin` aliases. Unsupported formats, fractions, concepts, units, and dimensional contexts are skipped with a warning while the original source remains available. Concepts use an exact local-name allowlist. Monetary facts require an ISO 4217 unit; employee counts require a pure count unit. Scope defaults to `unknown` unless the facts establish it; dimensional segment/geography facts are never generalized to company-wide observations.

All new extracted rows are stored as `FinancialObservation` and `Evidence` with `ReviewStatus.proposed`; this module never updates company records. Worker retries upsert by a stable source-fact key and preserve prior human review states. Incomplete, unsupported, or unquoted values are omitted rather than inferred.
